# Warden Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Claude Code plugin that enforces per-subagent and per-session usage budgets with hooks, records real 5h/7d limit percentages through a status line wrapper, and reports usage by source.

**Architecture:** One Node entry script per surface (`bin/warden-hook.js` dispatches on `hook_event_name`, `bin/warden-status.js` wraps the status line, `bin/warden-cli.js` backs `/warden`). Pure logic lives in small `src/` modules with no I/O where possible; I/O is confined to `src/store.js` and `src/transcript.js`. All persistent data under `~/.claude/warden/` (overridable with `WARDEN_HOME` for tests).

**Tech Stack:** Node.js ≥ 18, CommonJS, zero npm dependencies, tests with `node:test` + `node:assert/strict`.

**Spec:** `docs/superpowers/specs/2026-11-25-warden-design.md`

## Global Constraints

- Zero runtime dependencies; `package.json` has no `dependencies`.
- Any uncaught error in a hook → allow the call (exit 0, no output) and append the error to `~/.claude/warden/errors.log`.
- No network calls anywhere.
- Hooks print nothing unless a threshold action fires.
- Each warning fires once per threshold per scope (`warned` set stored in agent/session record).
- Hook p95 < 50 ms; transcripts read incrementally from a stored byte offset.
- Atomic state writes (write `*.tmp` then `rename`); ledger is append-only JSONL.
- Cost-weighted tokens = `input + output + cache_creation` + `0.1 × cache_read`.
- Defaults (subscribers): subagent 2% of week, or 1,500,000 cost-weighted tokens when % unavailable; 45 min; 250 tool calls; max depth 2; max concurrent 4; loop warn 5 / stop 8 identical calls in 10 min; weekly warn ≥ 80%, ask ≥ 95%; pace warn when 5h window projected to run out in < 30 min; ladder warn 75%, stop 100%, hard stop after 5 denials.
- Defaults (dollar mode): subagent $3, session $20 (warn 75%, ask 100%).
- Commit after every small change (user request).

## Review Focus

1. Transcript line half-written when read (no trailing newline) → that line is skipped and re-read next time, never double-counted. (Task 3)
2. `rate_limits` absent (API user, or before first response) → falls back to tokens/dollars without throwing. (Tasks 5, 7)
3. Two hook processes update the same agent record at once → no corrupt JSON; worst case one increment lost. (Task 2)
4. User's original status line command fails or doesn't exist → Warden still prints its badge and exits 0. (Task 9)
5. Malformed config file → defaults used, one warning logged, hooks keep working. (Task 1)

### Task 4: Budget ladder (pure)

### Task 7: Hook dispatcher

**Files:** Create `bin/warden-hook.js`, `hooks/hooks.json`, `src/hooks.js`, `tests/hooks.test.js`

**Interfaces — Consumes:** Tasks 1–6. **Produces:** `handle(evt: HookInput, now: number): HookOutput|null` (pure-ish; tests call it directly) and the CLI wrapper that reads stdin, calls `handle`, prints JSON, and fails open per Global Constraints.

Behavior by event:
- `SessionStart`: snapshot baseline; run `checkWeekly`; warn via `additionalContext` once.
- `SubagentStart`: create agent record `{depth: parentDepth+1, startedAt, weekPctAtStart}`.
- `PreToolUse`: if spawn tool → `checkSpawn` + `checkWeekly` (ask ≥ 95%); always → `checkLoop`, then `ladder.evaluate` for the calling agent. `deny` → `permissionDecision:"deny"` + reason, increment `denials`; `hardstop` → `{continue:false, stopReason}` (or keep denying if Task 0 says it ends the session); `ask` → `permissionDecision:"ask"`.
- `PostToolUse`: `account()`, update record and ledger; ladder `warn` → `additionalContext` `"Warden: ~25% of your budget left. Start wrapping up."`; `checkPace`.
- `SubagentStop`: close record, write ledger summary entry `{type:'agent', id, agentType, tokens, usd, weekPct, stoppedByWarden}`.
- Mode: `limits` when latest state has `rate_limits`, else `dollars`; `cfg.mode` forces it.

`hooks.json` registers every event above with `"command": "node \"${CLAUDE_PLUGIN_ROOT}/bin/warden-hook.js\""`, matcher `*` for tool events, timeout 5.

- [ ] Test: subagent over 2% week → PreToolUse deny with exact reason; 6th denial → hardstop.
- [ ] Test: spawn at depth 2 → deny; at 95% weekly → ask.
- [ ] Test: no state file at all → every event returns `null` or allow (Review Focus 2).
- [ ] Test: `handle` throws (inject bad input) → CLI exits 0, prints nothing, `errors.log` has one line.
- [ ] Test: warning emitted once across two PostToolUse calls.
- [ ] Red → implement → green → commit per file.
